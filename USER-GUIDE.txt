DiscForge CHD 2.5.0 - Windows x64 - 2026-09-30

Version 2.5: RAM extraction is selectable with more than 12 GiB total and at least 5 GiB free physical memory. An existing verified RAM drive is still required: select it in Settings. Without one, extraction falls back to disk and logs why. Memory and capacity are checked again for each archive. No driver or RAM drive is installed.

Select at least one CD codec, and one DVD codec for PS2 or automatic detection. The app explains missing selections before work starts. Compatibility with older devices creates CHD v4 with zlib and fixed hunks (CD 9792 bytes; DVD 2048 bytes); modern codec/hunk controls are disabled. Files can be larger and compatibility depends on device firmware. Missing PS1 cover images fall back to Libretro thumbnails.

Extract the COMPLETE win-x64.zip archive and run DiscForge-CHD.exe at its root. Keep every folder from the archive together. The ? buttons explain each option; advanced settings are initially collapsed. The header and About tab show the application name, version and build date.

Requires Windows 10 2004 (19041) or newer. .NET 10 and Windows App SDK are included. The WebView2 Runtime is needed for covers but not for conversion: https://developer.microsoft.com/microsoft-edge/webview2/

Choose input, output, platform, hunk sizes, codecs and thread count. Select up to four distinct codecs per media type using checkboxes. CD: cdlz, cdzs, cdzl, cdfl. DVD: lzma, zstd, zlib, flac or huff. PS2 uses createcd for CD (default 2448-byte hunk) and createdvd for DVD (default 2048-byte hunk). There is no second encode. PS1 optimizes existing CHDs and keeps the original when smaller after verification. Thread count defaults to the machine's logical processor count.

SharpCompress is the only archive extractor. The 7-Zip application and DLL are no longer included; unsupported or corrupt archives fail safely. Corrupt, encrypted, linked or unsafe paths are rejected. The disc is inspected before checking existing outputs, so archives are extracted even on a resumed run. Multi-track CUE files are preserved; safely numbered BIN tracks without a CUE use a temporary reconstructed CUE. Sources are retained because pregaps and indexes may be unknown. Nested TAR formats are processed in two steps.

Redump/PSX Data Center lookup works for CDs and DVDs. Output names use Game Name [SERIAL].chd. Without identification, ISO images up to 400 MiB are treated as CD and larger ones as DVD. PS2 covers are requested regardless of the media lookup result. Covers are cached and retried during a task; a cover failure does not stop conversion.

The entry timer includes identification, extraction, encoding and verification. CPU and read/write throughput (MiB/s) represent DiscForge CHD and its launched tools. Unavailable counters show N/D; metrics refresh every second.

Delete original archives is disabled by default. Original volumes are removed only after all discs from that input were created in the current run and their CHDs verified. Existing outputs, standalone images and failed entries are not deleted. Stop finishes the current entry; closing while busy requests the same stop.

Logs: input/temp/log.txt. Cache: %LOCALAPPDATA%/CHD Optimizer. Conversion does not use BAT or PowerShell; scripts are only for build and publication. Bundled chdman: MAME 0.289 (unknown), 2026-09-14, C++20/GCC 16.2/Zen 3. The in-app changelog lists features and fixes since the first C# version (1.2.0).

Version 2.2 adds Stop Now, codec checkboxes and a Settings tab for selecting external chdman.exe. The input folder is remembered and changing it defaults the output to its otimizados subfolder. CPU and I/O indicators measure the application and its child tools. Distinct game revisions receive distinct output names. When a safe multi-track BIN set has no CUE, a temporary CUE is generated; because original pregaps and indexes cannot be recovered, the source archive is retained. PS1 covers come from xlenore/psx-covers.

Version 2.3 adds disc-based PS1/PS2 detection. Automatic mode selects the system; manual mode rejects mismatches or unidentified discs. The interface supports English and Brazilian Portuguese, codec/hunk guidance and Reset defaults. Report issue creates a diagnostic ZIP of up to 10 MB and opens an email draft with the attachment for review; nothing is sent automatically. Crash logs: %LOCALAPPDATA%/DiscForge CHD/logs. Bug reports: andrethiesen@live.com.

Version 2.4: Select an existing RAM disk folder in Settings and enable RAM extraction. It is available only with more than 12 GiB total RAM and at least 5 GiB free. Before each archive, the app checks expanded size and volume capacity while reserving memory for Windows and chdman. Insufficient memory or an unavailable RAM volume falls back to disk with an explicit log message. Only this task's temporary folder is removed; the user's RAM disk is never unmounted. CHD output remains on disk. No RAM disk driver is installed by the application.

Supported RAM volumes: Windows RAM drive type and ImDisk memory drives. Existing drive/Windows settings may allow paging; reduced intermediate writes do not guarantee zero disk traffic.
